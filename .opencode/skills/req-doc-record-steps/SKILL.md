# 需求文档 → 原子交易录制步骤表

**图片查看统一规则**：为录制解析界面原型或截图时，所有主模型均使用 [qwen-record-replay-vision](../qwen-record-replay-vision/SKILL.md)，调用项目 `opencode.json` 中的 `Qwen3.8-27B`；调用失败时报告，不自行看图或切换模型。

把需求文档（含界面原型）转成**两列步骤表**（交易名称 | 操作步骤描述），每行一个原子交易，
步骤描述必须达到「交给 AI（playwright-ui-recorder skill）就能完成 UI 录制」的粒度。
本 skill 是 `playwright-ui-recorder` 的**上游**：产出的表格就是它的阶段 1「原子交易清单」输入。

```
需求文档(docx) ─► ①类型识别 ─► ②目录解析+章节摘要 ─► ③界面原型解析(必做)
                                                      │
⑥输出表格文件+自检 ◄── ⑤编写操作步骤(两列表格) ◄── ④拆分原子交易
```

3. 在上方注册表加一行；
4. 按该文件约定执行流程。
**不要**把新类型的规则混写进 SKILL.md 主文件。

## 阶段 0：输入确认（缺什么问什么）

| 参数 | 说明 |
|------|------|
| 文档路径 | 工作区内的 docx（缺了用 glob 找 `*.docx` 列给用户选） |
| 录制范围 | 章节号（如 3.2）或「整篇」；默认问 |
| 不录项 | 用户指示跳过的功能（如外部依赖 OCR/联网核查）；默认问，可先按「外部依赖不录」预填待确认 |
| 输出路径 | 默认 `work/<任务目录>/transactions-<模块名>.md` |

## 阶段 1：解析文档

1. **目录解析**（复用 `document-catalog-parse` skill 的脚本，图片自动抽到 `assets/`）：
   ```
   python E:\智能平台\autotest-line\llm-tools\skills\document-catalog-parse\scripts\parse_docx_catalog.py <docx> -o work/<任务目录>/catalog.json
   ```
2. **章节摘要**（本 skill 脚本）：
   ```
   python .opencode/skills/req-doc-record-steps/scripts/make_section_digest.py work/<任务目录>/catalog.json <章节号> -o work/<任务目录>/
   ```
   产物：`section-<n>.json`（原始子树）/ `digest-<n>.txt`（`### 章节号 标题` + 正文 + `[TABLE]` + `[IMAGE assets/xxx.jpg]`）/ `imglist-<n>.md`（章节号→图片绝对路径）。
3. **通读 digest**：按章节顺序建立「页面/按钮/场景」结构认知；`操作权限` 表的按钮清单 = 交易完整性基准。
4. **解析界面原型（必做，不可跳过）**：对 digest 中每个 `[IMAGE assets/xxx.jpg]`（界面原型小节），
   用 **Read 工具直接读图片**（多模态），写结构化描述到 `work/<任务目录>/prototypes/<章节号>-<序号>.md`：
   - 页面类型：列表页 / 表单主页 / 抽屉 / 对话框 / 浮层；
   - 查询区：字段名 + 控件形态（文本框/下拉/日期），是否有【更多】折叠区；
   - 按钮清单及位置（工具栏/表行内/底部）；
   - 列表列 / 表单字段顺序（与业务要素表对照）；
   - 分页、tab、子页、联动区。
5. **三方交叉核对**（原型 vs 业务要素表 vs 操作权限表）：
   - 原型有、要素表无 → 标注「原型独有」；要素表有、原型无 → 标注「表独有」；
   - 按钮不在操作权限表 → 不生成交易；
   - 字典选项（下拉可选项）以要素表「规则及说明」里的字典项明细为准。

## 阶段 2：拆分原子交易

拆分约定（以 `doc-types/<类型>/DOC-TYPE.md` 为准，tansun-credit 类型已验证规则）：

1. **一个具体操作功能 = 一个原子交易**：查询、重置、新增、修改、查看、删除、行内按钮（法院信息/影像资料…）各自独立；
2. **分支 = 选择不同选项导致页面/流程不同 → 每个分支一个交易**（如 新增→潜在客户场景 / 担保公司场景 / 正式客户场景）；
3. **同一按钮的多个校验规则合成一个交易**（如 新增保存校验：必输项/位数/已存在 三规则一单）；
4. **组件块 = 独立原子操作**：场景页按 tab/组件块拆分，每块一个交易（如 概况/客户标签/股东及关联人/经营情况 各自维护）；
5. 只录文档实际描述的内容：文档写「同上/同XX场景」且无差异化内容的 → 不录，记入不录项；
6. 不录项（用户指示跳过、外部依赖、文档未实现）列在输出文件末尾，**不混进表格**。

交易命名：`<页面/列表> - <操作>（<场景/范围>）`，如 `列表-查询`、`新增-潜在客户场景`、`修改-潜在客户场景`、`法院信息（弹窗）`。

## 阶段 3：编写操作步骤（两列表格，核心规范）

### 3.1 表格格式

| 列 | 内容 |
|----|------|
| 交易名称 | 见 3.2 命名 |
| 操作步骤描述 | 线性步骤序列，`1)` `2)` `3)` 编号，步与步之间用 `；` 连接（单元格内不换行，便于直接导入） |

每步 = **一个 AI 可执行动作**：`动词 + 目标(控件名) [+ 值/选项] [（数据说明）] [，验证: 期望结果]`。
动词集：`点击 / 输入 / 选择 / 展开 / 勾选 / 打开 / 进入 / 返回 / 验证`。

### 3.2 写入/不写规则（用户硬约束）

**不写**：
- **点击菜单进入目标页面的步骤**：如 `【客户管理】→【客户信息维护】→【对公客户管理】` 这类顶层菜单导航一律不写；
  目标页面及入口菜单改写到**文件头**（`> 目标页面: ...（入口菜单: ...，不录）`）；
- **不可操作的页面状态描述**：如「页面加载完成」「底部显示分页」「列表按创建时间倒序展示」
  「系统展示客户查询条件和对公客户列表」等纯展示/状态说明，一律不写。

**必须写**：
- **二级页面/弹窗/抽屉/浮层/场景页的进入步骤**：`点击【新增】按钮，打开「新增客户校验」抽屉`、
  `点击【修改】按钮，进入场景修改页`、`点击【法院信息】按钮，打开「法院信息查询列表」对话框`——
  这是操作上下文切换，AI 录制必须知道在哪里操作；
- 页面自动跳转后的上下文说明：`创建成功后页面进入「维护对公客户概况」页，后续操作在该页进行`。

**保留为「验证」步**（可断言的状态才写）：
- 系统默认值：`验证: 「客户状态」默认显示为「信贷预客户」`；
- 提示文案（用文档原文）：`验证: 未选记录时提示「请选择有效数据」`；
- 保存/暂存结果：`验证: 接口返回 200`；列表命中：`验证: 列表刷新命中 1 条`；
- 清空结果：`验证: 8 项查询条件全部清空`。

**断言保守性 + 文档与实测冲突处理**（重要，防复刻失败）：
- **只断言已探路/已实测验证过的行为**，不要把文档描述直接当断言：
  - 系统自动带出/生成的字段（如弹窗自动带出客户编号/名称/证件号码）**不纳入清空/变化断言**——例：法院信息弹窗【重置】只断言用户可填的「法院信息类型/是否有效」清空，自动带出 3 项不在已验证清空范围；
  - 校验类断言的前提条件要写对——例：「必输项 4 条内联报错」只在**全空表单**点保存时出现，先选了类型再断言 4 条会只剩 2 条；
  - 字典未配置的下拉 → 断言「0 个选项」而非猜测选项值；
- **文档与实测冲突时以实测为准**，并在相关步骤加「注」说明差异（提示文案/默认值/控件形态/功能是否实现），如 `注: 实测查询接口忽略「客户分类」参数`、`注: 文档「更多展开」实际未实现`；
- **校验类交易（多规则合一单）的步骤顺序必须与真实校验逻辑一致**：先做「全空表单」规则，再做单项规则（顺序颠倒则断言不可达）。

### 3.3 数据说明约定（每笔交易的数据策略要写进步骤）

| 占位 | 用在哪 | 写法 |
|------|--------|------|
| 生成数据 | 新建类交易 | `（生成数据: AT_潜客_yyyyMMddHHmmss）`、`（生成数据: 随机 18 位统一社会信用代码，9135 前缀）` |
| 列表首行 | **仅纯查询/重置类交易**（不创建数据、目标操作不依赖特定行） | `（取列表首行的「客户编号」值）` |
| 前缀+状态过滤 | 修改/查看/行按钮类交易（须命中特定场景的行，首行不可靠——首行可能是正式/注销客户会落错场景页） | `（「客户名称」查询框输入「AT_潜客」前缀模糊查询 + 排除客户状态含{合并注销/合并中/注销}取首行，找不到则 FAIL 并注明）`，并在文件头注明依赖哪笔前序交易创建的数据 |
| 固定存量客户 | 「已存在/唯一性」校验类交易（须用已知存在的数据，防首行数据漂移） | `（固定已存在客户: 名称/证件号，已验证存在，如列表第 2 行 杭州云测九一五科技有限公司/91350400563703658G）` |
| 固定选项 | 字典/不可筛选字段（或接口忽略该参数时兜底） | `（固定选项: 发展巩固类）` |

### 3.4 粒度约定

- 按钮/弹窗/页面跳转/断言 = 独立步骤；
- **组件内全字段录入不必逐字段展开**：写 `按 §<章节号> 业务要素将【<组件名>】组件全部字段按页面视觉顺序录入`
  （文本框按规则输入、下拉选值、按钮类字段按对应弹窗流程完成）——录制引擎（fillEngine）按盘点自动逐字段填充；
- 校验规则类交易（如 C3 保存校验）：每个规则一组步骤 `输入<违反规则的数据> → 点击【保存】 → 验证: 提示「<文档原文>」`；**规则顺序必须与真实校验逻辑一致**（「必输项」规则=全空表单直接点保存，必须放在任何选择/输入之前，否则 4 条报错只剩部分条数、断言不可达）。

### 3.5 取值规则与降级路径（组件全字段录入步必带）

「按业务要素将组件全部字段按页面视觉顺序录入」一步**不能只写「按规则输入」**，必须让执行 AI 能确定性决定每个字段填什么、遇到环境差异怎么办。写法：文件头放一段「取值规则通用块」，各交易的录入步引用它（`取值规则见文件头通用块`）。通用块必含：

- **取值规则**：自由文本字段=生成数据 AT_ 前缀；下拉字段=首个选项（无选项跳过；**必填下拉若无选项→停止并 FAIL 留痕（字段名+截图），不得留空继续**）；日期字段=具体合法日期（输入后**主动关闭日期面板**）；开关=切换选中；只读系统反显=跳过；
- **特殊控件子流程**：地址选择器（省/市/区/详细地址固定值）、行业树（搜索过滤+首个可见叶子节点）、放大镜【引入】（查询→选择→回填）、测算类按钮（点击触发、回填结果不断言）；
- **0 记录降级**：放大镜/列表无数据 → 点【取消】跳过、字段留空（注明非必填），并写明环境事实（如「本环境对私放大镜 total=0」）；**禁止写「选择后回显」这类在无数据环境不可能完成的动作**；
- **不可达 happy path**：【保存】被真实短信核验/外部校验拦截 → 交易以【暂存】收尾并注明原因；
- **嵌套按钮（button-in-button）**：目标按钮嵌在小节头/另一按钮内时，必须写明定位方式（按 innerText 精确匹配可见按钮）+ 警告模糊匹配误中的副作用（如点中小节头会折叠小节）；
- **跨交易数据依赖**：某交易使用前序交易创建的数据时，文件头「数据依赖」区 + 该交易步骤内都写明（前缀查询+状态过滤+找不到 FAIL 兜底）。

### 3.6 黄金样例（tansun-credit 类型，A02 已验证+已按实测校准）
