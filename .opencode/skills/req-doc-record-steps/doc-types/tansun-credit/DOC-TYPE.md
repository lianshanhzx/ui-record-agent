## 识别特征

- 文件名：`A##|B##天阳信贷管理系统-*需求分册*.docx`；
- 章节标题带 `RQM_META1<base64>` 元数据后缀（`make_section_digest.py` 自动剥离，含 `entryNum`/`cmptAss`(页面编号如 ZJJK00066153)/`cmptType` 等）；
- 章节骨架（按出现顺序）：
  ```
  N.功能描述          功能的一句话描述
  N.操作权限          表格: 机构层级|角色|操作权限(【按钮】清单)|数据权限
  N.操作步骤          菜单路径【A】→【B】→【C】 + 步骤1~N（含「系统展示…」「系统提示…」描述）
  N.界面原型          [IMAGE] 界面原型图（可能多张：主页/抽屉/弹窗/场景页）
  N.业务要素          输入要素表 + 输出要素表
                      列: 字段名称|字段编码|类型|长度|是否必填|显示类型|默认值|规则及说明

  N.x.[按钮名]按钮规则  每个按钮一个子节（【查询】【重置】【新增】【暂存】【保存】…）
  ```
- 深层章节 = 场景页/弹窗/组件块（如 3.2.1.3.2.1=新增抽屉、3.2.1.3.3=场景页组件、3.2.1.7=法院信息弹窗）；

## 拆分约定（A02 实战验证）

1. **一个具体操作功能 = 一个原子交易**：
   - 列表页：查询 / 重置 / 新增（入口）/ 修改 / 查看 / 行内按钮（联网核查、法院信息、影像资料…）各自独立；
   - 查询交易必须覆盖**全部查询框**（基础区 + 【更多】展开区），不做「只录主流程」的裁剪；
2. **分支 = 选择不同选项 → 页面/字段集/流程不同 → 每分支一个交易**：
   A02 实例：新增后按「对公客户类型/客户状态」进入 3 个场景（潜在客户/担保公司/正式客户）→ C4/C5/C6 三单；
   修改/查看同理按场景拆；
3. **同按钮多校验规则 = 一个交易**：新增【保存】的 必输项校验/证件号 18 位/证件号已存在 三规则合成 C3 一单
   （每组规则 = 输入违规数据 → 点保存 → 验证提示文案/接口 code）；
4. **组件块 = 独立原子操作**：场景页按 `[aria-expanded]` 分节（对公客户概况/客户标签/股东及关联人信息/经营情况），
   每组件 = 1 笔交易（各自盘点+填充+暂存）；正式客户场景下文档写「同担保公司」且无差异化内容 → 不录，记不录项；
5. **文档没写的不录**：文档「同上/同XX」引用无独立内容 → 不录；原型有而文档未描述功能的元素（如装饰性图标）→ 不录；
6. **外部依赖默认不录**（待用户确认）：OCR 识别（依赖外部 OCR 服务）、联网核查（依赖外部核查服务）等；
7. 交易命名：`<页面> - <操作>（<场景/范围>）`，编号 C1、C2…按清单序（自然序=后续回放执行序）。

## 操作步骤编写细则（本类型）

通用规则见 SKILL.md 阶段 3。本类型补充：

- 「操作步骤」小节的菜单路径（`【客户管理】→【客户信息维护】→【对公客户管理】`）= 目标页面入口，
  只写进文件头，不写进表格；其后的「步骤1~N」是页面内操作来源，需按 3.2 规则过滤后转写；
- 「系统展示…」「系统按…展示」类句子：
  - 纯展示（分页、排序、列清单）→ 丢弃；
  - 含默认值/显隐（`客户状态默认显示为「信贷预客户」`、`默认展示…隐藏…通过【更多】展示`）→ 转写为「验证」步；
  - 含条件行为（`未选择记录时系统提示「请选择有效数据」`）→ 转写为「验证」步（提示文案用文档原文）;
- 按钮规则子节 → 直接映射交易的步骤+验证：
  - 【查询】：录入方式说明（哪些下拉/哪些文本框）决定步骤动词；
  - 【重置】：验证步 = 列出**用户可填**的被清空字段（系统自动带出字段不纳入清空断言，以实测为准）；
  - 【保存】/【暂存】：验证步 = 接口 200 + （新建类）列表反查命中 1 条；
  - 【返回】：独立步骤（回列表）+ 反查步（重输行内名称→查询→断言在列），不合并到上一步；
  - **校验规则类交易顺序以实测为准**（如「必输项」校验=全空表单直接点保存，必须先于任何选择/输入）；
- 业务要素表「是否必填=是」且无默认值的字段 → 步骤必须录入（生成数据/列表首行）；
  「系统反显」字段 → 不录，（修改类交易里）作为「只读跳过」说明；
- 场景页路由：新增【保存】后按所选类型自动进入对应场景页（URL viewType/场景参数）→ 写「进入」上下文句；
- 行内按钮交易（法院信息/影像资料）：首步固定为「勾选列表记录行单选框」（文档：未选记录提示「请选择有效数据」）；
  弹窗内操作全部带「对话框内/弹窗内」限定词。

## 已知文档-系统差异（A02 探路实证，写步骤时注意）

- `findCustCorporatList` 接口**忽略 rtgCstClId（客户分类）参数** → 查询交易里该字段选固定选项，断言只到「参数已发出」；
- 列表「客户分类」列恒空（接口不返回）→ 取列表首行的字段若为空，改用固定值并在步骤标注；
- 文档「更多展开客户名称/证件号码」未实现（法院信息弹窗仅 T 形图标）→ 按实际不录，记不录项；
- 字典未配置的字段（文档注明「未获取到字典项」）→ 断言「下拉 0 个选项」，不猜选项值；
- **客户状态默认值**：文档写「潜在客户」，实际系统显示「信贷预客户」（cstSt=2）→ 以实际为准并「注」标注；
- **新增【保存】校验「必输项」**：4 条内联报错（请选择对公客户类型/请选择证件类型/请输入客户名称/请输入证件号码）仅**全空表单**点保存时出现，纯前端无 API → 校验交易顺序=先全空规则再选类型；
- **已存在校验**：走 checkCustCorporat 接口 code=100（description 含「已有证件号码相同但客户号不同的记录，请传入记录ID更新」）；
- **法定代表人/负责人三项**：disabled 只读，仅可经【引入】对私客户放大镜回填；本测试环境对私放大镜 total=0 → 步骤写「输入 AT 查询，无记录点【取消】跳过、留空（非必填）」，**禁止写「选择后回显」**；
- **场景页 button-in-button**：「对公客户概况」小节头内嵌套小号 保存/暂存/返回 文字按钮 → getByRole 拿不到、hasText 误中折叠小节，须 innerText 精确匹配可见按钮；【返回】须点底部 primary 主按钮；
- **【保存】happy path 被真实手机短信核验拦截** → 担保公司/正式客户场景以【暂存】收尾（saveDBCustCorporat/saveCustCorporat），暂存不强制校验；
- 法院信息弹窗【重置】**只清空用户可填项**（法院信息类型/是否有效），自动带出的 客户编号/名称/证件号码 不在已验证清空范围；
- 修改/查看/法院信息/影像资料选行数据源：**「AT_潜客」前缀模糊查询 + 排除{合并注销/合并中/注销}取首行**（列表首行不可靠，可能是正式/注销客户会落错场景页），依赖前序新增交易创建的数据，找不到 FAIL。
